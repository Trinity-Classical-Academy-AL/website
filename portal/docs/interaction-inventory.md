# Portal interactions (Lane C)

Baseline: `perf/optimistic-ui` before this change. Forms below are source occurrences; PortalLayout and AuthLayout currently duplicate their content for desktop/mobile. The enhancement never assumes that duplication or a `-m` suffix. All URLs, payload names, handlers, sessions, cookies and confirmation destinations remain server-owned.

## Shared treatment

- **Enhanced POST**: signed-in portal forms opt in with `data-enhance`. Capture FormData including the submitter before disabling it; one request through ClientRouter's preparation loader; same-origin redirects and Set-Cookie retain browser behavior. Keep the document visible, suppress repeated submits, show button busy text/spinner only after 150 ms. Do not automatically retry an uncertain network failure.
- **Close sheet**: hide the open overlays synchronously; preserve their actual nodes and all entered values. The server's HTML replaces them on success. Network errors, non-2xx responses, `.alert-err`, or error field alerts restore the snapshot and show the server message as text in a polite toast. Existing server success notices remain authoritative; inquiry saves also announce a polite success toast. Server field validation is applied to the preserved inputs without replacing their draft values.
- **Remove**: document/event delete confirmations also hide matching `data-row` copies. Confirmation is still required. **Status**: inquiry selects update immediately and restore the committed controlled select value if rejected.
- **Security/settings**: no optimistic claim that an email/password/permission change succeeded. Existing Ark dialogs can close optimistically; server error responses restore them. Google links and the email-first sign-in POST retain full navigation because they may leave the origin for OAuth.
- **Instant overlays**: the tour add sheet and known event/document/tour delete, prospect enrollment and form reminder confirmations are already rendered hidden. Clicking opens locally with replaceState; query-string deep links and no-JS requests render the same visible content. Esc, close and Tab trapping apply to plain SSR dialogs; Ark keeps its own focus handling. Other sheets use Astro tap prefetch. No prefetch issues a mutation.
- **Search**: `form.tools` q inputs navigate after 200 ms with history replace, preserve tab and named filters, persist each responsive input through swaps, and retain caret/focus/scroll. Unfiltered family/prospect/booking/document pages contain their complete authorized row set, so they filter immediately in the DOM and replace the URL. Initially filtered pages use server navigation to recover complete results; tabs and named filters survive.
- **Same-page saves** preserve scroll and restore the previous named/identified control where it remains, otherwise focus the visible heading. No page clearing or skeleton insertion.

## Every form at baseline

“Current URL” means the page's existing frontmatter POST handler. Exact named fields distinguish separate actions even where their source is a one-line form. Auth POSTs remain on Astro's native transport; the signed-in enhancement is deliberately not used to guess authentication outcomes. Downloads use their existing GET endpoints.
